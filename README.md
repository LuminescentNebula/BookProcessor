# BookProcessor

Скрипт обрабатывает фотографии книг локальной мультимодальной моделью через
[Ollama](https://ollama.com/). Каждая непосредственная подпапка корневой папки
считается коробкой. Изображения внутри сортируются по имени (с учётом чисел) и
берутся попарно: **обложка**, затем **страница с выходными данными**.

## Установка

Установите Docker с Docker Compose и Ollama отдельно от этого проекта. Запустите
Ollama на хосте или на другом сервере и загрузите vision-модель:

```bash
ollama pull qwen2.5vl:7b
```

Нужна vision-модель Ollama, способная принимать изображения. Можно выбрать
другую локально установленную модель, в том числе более крупную.

## Запуск

### Docker и веб-интерфейс

```bash
PHOTOS_PATH=/абсолютный/путь/к/фотографиям \
OLLAMA_API_URL=http://host.docker.internal:11434 \
  docker compose up --build
```

`OLLAMA_API_URL` — полный адрес и порт уже запущенной Ollama. Для Ollama на
другом компьютере укажите, например, `http://192.168.1.50:11434`. Значение по
умолчанию — `http://host.docker.internal:11434`. В Linux Ollama на хосте должна
принимать не только loopback-подключения; например, её можно запустить с
`OLLAMA_HOST=0.0.0.0:11434 ollama serve`. Не публикуйте этот порт в недоверенной
сети.

Откройте `http://127.0.0.1:5000`. Выбирать путь или коробки в интерфейсе не
нужно: каждая подпапка mounted-каталога автоматически становится коробкой и
добавляется в очередь после того, как её содержимое не менялось 10 секунд.
Новые подпапки можно добавлять во время работы приложения. Результаты будут
сохранены в PostgreSQL. Docker Compose запускает только приложение и PostgreSQL;
Ollama продолжает работать отдельно по адресу `OLLAMA_API_URL`. Данные
PostgreSQL сохраняются в volume `postgres_data`.
Во время обработки страница раз в секунду обновляет прогресс-бар и немедленно
добавляет каждую распознанную книгу в таблицу. Рядом отображается длительность
текущего запроса в формате `часы:минуты:секунды`. Перезагружать страницу не нужно.

Первый запрос после запуска медленнее, поскольку модель загружается в память.
По умолчанию тайм-аут одного обращения к модели увеличен до 1800 секунд, а модель
остаётся загруженной 30 минут. Фотографии перед отправкой автоматически
уменьшаются до 2048 пикселей по большей стороне, что существенно сокращает объём
запроса; предел можно изменить переменной `MAX_IMAGE_SIZE`. Если запросы всё равно не успевают завершиться,
сначала оставьте один поток и проверьте журналы отдельно запущенной Ollama, а
также доступность `OLLAMA_API_URL` из контейнера приложения. Тайм-аут задаётся
переменной `OLLAMA_TIMEOUT`.

В интерфейсе отображается текущее состояние Ollama, PostgreSQL и mounted-каталога, проверяемое каждые
5 секунд. При кратковременной потере Ollama запрос повторяется три раза с
увеличивающейся задержкой. Если PostgreSQL отключится уже после распознавания,
готовые строки останутся в памяти, интерфейс покажет ожидание базы, а приложение
будет автоматически пытаться сохранить их после восстановления соединения.
Уже успешно сохранённая версия папки повторно не обрабатывается даже после
перезапуска контейнера. Если добавить или заменить в ней фотографии, сигнатура
изменится и папка автоматически попадёт в очередь снова. Параметры автоматики
можно задать переменными `OLLAMA_MODELS`, `BOOK_WORKERS`, `OLLAMA_TIMEOUT`,
`FOLDER_SCAN_INTERVAL` и `FOLDER_STABLE_SECONDS`.

Веб-интерфейс содержит две страницы результатов:

* `/library` — карточки книг; при наведении карточка переворачивается и показывает
  вторую фотографию с издательской информацией;
* `/books` — таблица с сортировкой колонок по возрастанию и убыванию.

На обеих страницах можно искать по автору, названию, издательству и жанру либо
вводом текста, либо выбором известных значений из выпадающих списков.

Остановить приложение:

```bash
docker compose down
```

Посмотреть сохранённые книги:

```bash
docker compose exec postgres psql -U bookprocessor -d bookprocessor \
  -c 'SELECT id, box, author, title, isbn FROM books ORDER BY id;'
```

### Командная строка

Обработать все папки-коробки, используя один поток:

```bash
DATABASE_URL=postgresql://bookprocessor:bookprocessor@localhost:5432/bookprocessor \
  python book_processor.py /путь/к/фотографиям
```

Обработать только коробки `box-1` и `box-3`, одновременно до четырёх пар:

```bash
python book_processor.py ./photos --folders box-1 box-3 --workers 4 \
  --models qwen2.5vl:7b
```

Несколько моделей задаются через запятую. Они вызываются последовательно для
каждой пары, а в итог попадают первые непустые значения (это полезно, когда одна
модель не распознала часть полей):

```bash
python book_processor.py ./photos \
  --models qwen2.5vl:32b,llama3.2-vision:90b --workers 2
```

`--workers` по умолчанию равен `1`. Не ставьте значение выше возможностей GPU и
настроек параллелизма Ollama. Основной результат сохраняется в PostgreSQL;
параметром `--output books.xlsx` можно дополнительно создать Excel-копию.
Непарное последнее изображение
пропускается с предупреждением. Ошибка отдельной модели также не останавливает
остальные книги: соответствующие нераспознанные ячейки остаются пустыми.

Полный список параметров:

```bash
python book_processor.py --help
```
